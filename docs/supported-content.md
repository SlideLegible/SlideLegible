# Supported Content (MVP)

This matrix describes what the MVP analyzes and changes. Anything not listed is left untouched. Fixtures for each supported case are generated by `tests/fixtures/decks.py`.

## Text

| Content | Analyzed | Corrected | Notes |
| --- | --- | --- | --- |
| Text in shapes and text boxes (`p:sp`) | Yes | Yes | Including grouped shapes (group transforms are applied). |
| Placeholder text (title, body, subtitle, footer…) | Yes | Yes | Inherits layout and master placeholder list styles and master `titleStyle` / `bodyStyle` / `otherStyle`. |
| Table cell text | Yes | Yes | Explicit cell fills and table styles stored in `tableStyles.xml`. Built-in styles missing from the file make the cell color "uncertain" and it is not changed. |
| Hyperlink text | Yes | Yes | Theme `hlink` color unless the run already uses its own color; fixes add PowerPoint's hyperlink-color extension so the new color is used. |
| Fields (slide number, date) | Yes | Yes | Treated like runs. |
| Semi-transparent text | Yes | Yes | Composited over its background. Text with ≥ 50 % transparency is decorative and skipped. |
| Watermarks | Reported | No | ≥ 72 pt with contrast below 1.5:1 counts as decorative. |
| Gradient / picture-filled text | Reported | No | |
| WordArt (warped text) | Reported | No | |
| Charts, SmartArt, OLE objects | Listed as not analyzed | No | |
| Text in master/layout non-placeholder shapes | No | No | Their fills are still used as backgrounds. |

## Colors

Direct `srgbClr`, `schemeClr` (through the effective color map, including slide `clrMapOvr`), `sysClr`, `prstClr` (common names), `scrgbClr`, `hslClr`, and the transforms `tint`, `shade`, `lumMod`, `lumOff`, `satMod`, `satOff`, `hue*`, `alpha*`, `comp`, `inv`, `gray`, and RGB channel transforms. `phClr` is resolved for theme fill styles.

## Backgrounds

| Background behind text | How it is measured | Certainty | Correction |
| --- | --- | --- | --- |
| Solid slide, layout, or master background | OOXML | exact | Text color first; background lightness if needed (edited where it is defined, so layout/master edits reach every slide using them). |
| Solid shape or table cell fill (`spPr`, `fillRef`, table style) | OOXML | exact | Same as above; the fill is edited on its own shape/cell. |
| Text highlight | OOXML | exact | Text color only. |
| Semi-transparent solid layers | OOXML compositing | derived | Text color only. |
| Gradient | Rendered sample of the text area (stops without a renderer) | rendered estimate / derived | Text color if one color passes everywhere; otherwise flagged, not changed. |
| Picture | Rendered sample | rendered estimate | Semi-transparent scrim in the theme's dark or light color, then text color if needed. Needs a renderer. |
| Partly overlapping shapes, charts | Rendered sample | rendered estimate | Text color if one color passes everywhere. |

Rotated shapes use their unrotated box. The sampled area is the whole text box minus its insets, which is conservative for short text in large boxes.

## Package handling

Inputs are validated as ZIP/OOXML; path traversal entries, encrypted packages, and suspicious compression ratios are rejected; XML is parsed without entity expansion or network access. Outputs are new packages in which only the edited XML parts change; all other parts are copied byte-for-byte. Legacy `.ppt` files are not supported.
